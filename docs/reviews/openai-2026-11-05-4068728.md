## Part 6 of 6

Major, test/js/runtime_wizard.test.js:~58
wizardPage ignores the headHtml option, so tests that rely on a <base href> in the document head never actually set one. The test “W3 a control named action and a <base href> do not change the target” passes headHtml: '<base href="https://evil.example/">' to wizardPage, but wizardPage does not forward it to D.page. As a result, the test cannot fail even if the runtime were to resolve URLs incorrectly in the presence of a <base>, because no <base> is ever present.
Failure scenario: A regression causes the wizard to resolve the form action (or the fetched wizard URL) under an existing <base href>, producing incorrect targets on Redmine instances that inject a base tag. The test still passes because headHtml is discarded and no base tag is applied.
Fix: Plumb headHtml through to D.page (or inject it into the head before scripts load). For example:
async function wizardPage(opts) {
  const o = Object.assign({ body: F.read('wizard_entry') }, opts || {});
  const s = stubs(o.respond, o.load, o.form);
  const pg = await D.page(o.body, {
    url: o.url || URL_,
    meta: o.meta,
    head: true,
    headHtml: o.headHtml,   // add this line
    scripts: [D.LOADER, o.runtime === undefined ? D.RUNTIME : o.runtime, D.WIZARD],
    before: s.before
  });
  pg.log = s.log;
  return pg;
}
Additionally, consider adding a focused assertion that the <base> element is present in the built document in that test to prevent silent omissions in future.

Resolution: not a defect: wizardPage already passes headHtml to D.page (test/js/runtime_wizard.test.js:71), and D.page puts it in the head in both branches (test/js/support/dom.js:101 and the JSDOM call below it). Checked at runtime: a page built with that headHtml has document.querySelector('base').href and document.baseURI equal to https://evil.example/, so the test fails if the wizard resolves its URLs against the base. The reviewer saw the diff hunk without line 71.
